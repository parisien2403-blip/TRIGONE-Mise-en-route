TRIGONE — Mise en route — première version (le demandeur)
============================================================

MIS À JOUR : les vraies librairies (jsPDF, autotable, QR code) et les vraies icônes de TRIGONE ont
remplacé mes copies provisoires, et un service worker (identique dans sa logique à celui de TRIGONE
compte-rendu) permet maintenant l'installation et l'usage hors ligne.

CE QUI EST FAIT DANS CETTE VERSION
- Écran du demandeur (missionnaire, chef de cellule ou adjoint) : formulaire complet
  reprenant les champs de la DOMR papier (identité, CIE, mission/formation, ABT,
  trois trajets, nourri/logé à titre onéreux, demande d'avance, imputation, code
  FD@LIGNE, notes de service à joindre).
- Demande collective : possibilité d'ajouter plusieurs personnes sur une même demande.
- Panier : plusieurs demandes peuvent être préparées puis envoyées ensemble en un
  seul mail, pour ne pas multiplier les messages au premier signataire.
- Génération d'un PDF (une page par demande) reprenant les informations de la DOMR
  officielle, et d'un fichier .json qui portera la demande d'un signataire à l'autre.
- Relecture avant envoi (comme sur TRIGONE compte-rendu) : rappel de ce qu'il faut
  joindre au mail avant de l'envoyer.
- Noms des fichiers .json (grade et nom du 1er missionnaire) : « GRADE NOM - Demande d'OMR »
  (demandeur), « GRADE NOM - OMR Validation 1 » (1er valideur), « GRADE NOM - OMR Validation 2 »
  (2e valideur), « GRADE NOM - OMR Refus » (refus).
  À côté de « OMR » : INDIVIDUEL (un seul missionnaire) ou COLLECTIF (plusieurs).
- Onglet Alim./Héb. : réservation ABT (oui / non), reprise sur le PDF.
- Envoi en deux temps, pour le demandeur comme pour les valideurs (validation ou refus) :
  « 1. Enregistrer le .json » (sur PC, on choisit où le ranger), puis « 2. Envoyer »,
  qui ne s'active qu'une fois le fichier enregistré, ouvre le mail auquel on le joint.
- Trajets : gare / aéroport / port de départ et d'arrivée selon le moyen de transport ;
  voie routière civile (VRC) avec rappel des pièces à joindre (demande d'autorisation
  VRC, carte grise, assurance).
- Rien n'est perdu si l'application est fermée en pleine saisie (comme TRIGONE
  compte-rendu) : la demande en cours et le panier sont sauvegardés automatiquement
  sur l'appareil.
- Même identité visuelle que TRIGONE (couleurs, police, boutons, mode sombre).

SAISIE D'UNE DEMANDE
- Villes françaises : suggestions pendant la saisie et code postal rempli automatiquement (même
  service que TRIGONE compte-rendu : api-adresse.data.gouv.fr). Pays étranger au choix pour
  chaque lieu (liste des pays de TRIGONE compte-rendu).
- Matricule mis en forme automatiquement : 3 + 2 + 2 + 3 chiffres (ex : 067 50 10 191).
- Trajet retour pré-rempli avec l'aller inversé ; il suffit de le modifier si besoin.
- Code FD@LIGNE : le code engagement, le centre financier, le centre de coût, le code activité et
  le libellé s'affichent d'après codier.json (extrait du codier FD du 22/07/2026, relu automatiquement à chaque ouverture) et figurent
  dans le PDF. Un code clôturé est signalé avec son code de remplacement.
  Mettre à jour le codier : remplacer codier.json (colonnes CODE ENGAGEMENT, CENTRE FINANCIER,
  CENTRE DE COÛT, CODE ACTIVITE, LIBELLE ENGAGEMENT, FIN DE VALIDITE, CODE ENGAGEMENT DE
  DEVERSEMENT).

ACCUEIL
- Bouton principal « Nouvelle demande », liens « Importer une demande refusée », « Espace valideur »
  et « Vérifier une mise en route », et en bas les onglets Bibliothèque (demandes envoyées),
  Panier et Mon espace (identité et mails pré-remplis).

UN SEUL FICHIER QUI CIRCULE
- Le missionnaire joint sa NDS ou sa DAF (PDF, JPEG ou PNG, 10 Mo maximum) dans l'onglet
  Imputation. À l'envoi, il voit un aperçu du PDF et n'envoie qu'un fichier .json, qui contient
  la demande ET les pièces jointes (rangées sur l'appareil dans IndexedDB).
- Le 1er valideur importe ce .json, consulte l'aperçu et les pièces (📎), signe, et renvoie un
  seul .json au 2e valideur.
- Le 2e valideur ne voit lui aussi qu'un aperçu et envoie à l'assistant Chorus DT un seul .json.
- L'assistant Chorus DT l'importe dans « Vérifier une mise en route » : signatures et pièces
  contrôlées, puis « PDF avec NDS / DAF » génère le PDF à traiter (chaque demande signée suivie
  des pages de ses pièces jointes, assemblées avec vendor/pdf-lib.min.js).
- L'empreinte SHA-256 de chaque pièce fait partie de la demande signée : une pièce remplacée en
  cours de route est signalée en rouge et la demande ne peut pas être validée.

CIRCUIT DE VALIDATION SÉCURISÉ
- Le demandeur envoie le PDF et le .json au 1er valideur.
- Espace valideur : le valideur saisit son grade, nom, prénom, fonction et son code d'accès
  (un code pour le 1er valideur, un code pour le 2e, remis par l'administrateur). Le code
  déverrouille la clé de signature de son rôle, publiée chiffrée dans valideurs.json : le code
  lui-même n'est écrit nulle part.
- Le code n'est demandé qu'une fois par appareil : la clé déverrouillée est conservée sur le
  téléphone ou le PC sous forme non exportable (utilisable pour signer, jamais lisible), jusqu'à
  « Déconnexion ». Si l'administrateur remplace le code, l'appareil est déconnecté.
- Aucune page d'administration dans l'application : les codes ne sont visibles nulle part.
  Pour changer un code, une nouvelle clé chiffrée est publiée dans valideurs.json sur GitHub
  (seul un compte autorisé sur le dépôt peut le modifier) ; l'ancien code cesse alors de
  fonctionner, les validations déjà faites restent valables.
- Une fois connecté, le valideur importe les .json, valide (signature électronique du
  contenu exact de la demande) ou refuse avec un motif, une par une ou en lot.
  1er valideur -> .json au 2e valideur ; 2e valideur -> .json à l'assistant Chorus DT ;
  refus -> .json au demandeur, qui l'importe, corrige et renvoie.
- Toute validation faite par un valideur non habilité, ou toute demande modifiée après
  validation, est signalée en rouge (au 2e valideur et sur « Vérifier une mise en route »).
- Le PDF porte deux cases (1er valideur à gauche, 2e à droite) : nom, fonction, date, heure et
  empreinte de la signature. Les données signées sont intégrées au PDF : l'assistant Chorus DT
  le glisse dans « Vérifier une mise en route » pour contrôler les signatures.
- Code perdu ou divulgué, changement de valideur : créer un nouveau code pour ce rôle.

MISES À JOUR
- À chaque ouverture (et au retour sur l'appli), TRIGONE relit updates-manifest.json.
- Pour publier une nouvelle version : augmenter APP_CODE_VERSION dans app.js ET appCodeVersion
  dans updates-manifest.json (même numéro), avec un appCodeMessage décrivant les nouveautés.
  Les appareils en retard affichent « Mise à jour obligatoire », ceux déjà à jour « Nouveautés ».
- appMessageVersion / appMessage : message d'information affiché une fois à tout le monde.
- Bouton « Mise à jour » en haut à droite de l'accueil : vérification manuelle.

INSTALLATION
Comme TRIGONE : déposez tous les fichiers (index.html, app.js, manifest.json, le
dossier vendor/) à la racine d'un même espace d'hébergement.
